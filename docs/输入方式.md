# 输入方式（会话鼠标驱动）

ok-gf2 的鼠标点击默认走 **Interception 会话鼠标**（`src/core/session_mouse.py` + `src/core/gf_interaction.py`），
键盘（ESC 等）仍走 PostMessage。两种方式切回原来的 `GenshinInteraction`（PostMessage），行为和以前一样：

- Qt 界面「捕获」页的输入方式列表里选 `Genshin`（`src/config.py` 里 `interaction` 是 `[GfInteraction, "Genshin"]`，默认第一项）；
- 或者设置页「输入 / 会话鼠标驱动」关掉。

绑定不到设备（没装驱动、不在 RDP 会话）时也会自动退回 PostMessage。

## 为什么要换

实录 2026-10-20：ok-gf2 和游戏一起跑在同一台机器的一个独立 RDP 会话里（2560x1440 全屏，主桌面留给人用）。

- 第 9 章「支援单位」的新手引导只认真实鼠标输入，PostMessage 点不动，推图卡死在部署界面；
- 游戏一旦被激活（真实点过一次之后），PostMessage 的点击会落到真实光标所在处，而不是消息里的坐标。

## 原理

- 需要用户自己装好 [Interception](https://github.com/oblitum/Interception) 内核驱动（`System32\drivers\keyboard.sys / mouse.sys`），本仓库不附带驱动，也不会替你安装；没装就自动走 PostMessage。
- 启动时打开 `\\.\interception10~19`，只认硬件 ID 为 `TS_INPT\TS_MOU` 的 RDP 鼠标；往每台候选设备写一条
  无位移、无按键、带随机标记的报文，用 RAWINPUT 看本会话收到的是哪一台，**设备号不写死**（每个会话分到的设备号不同），
  识别不到就报错退回 PostMessage，绝不往别的桌面乱点。
- 点击 = 绝对坐标移动（0~65535 映射到会话虚拟桌面）→ 按下 → 抬起，等价于内核级真实鼠标，游戏分不出来；
  只动本会话的光标，控制台的鼠标不受影响。
- 真实点击落在光标下面的窗口，所以点之前如果游戏不在前台会先 `bring_to_front`；app 窗口会被全屏游戏盖住，
  看进度用 web 页面即可。

## 不满足条件时

- 不在 RDP 会话（控制台桌面）、没装 Interception、设置里关掉：日志里有「会话鼠标不可用，退回 PostMessage」。
- 单次点击失败（坐标出了桌面、设备报错）：那一下退回 PostMessage 并记警告。
