# 新版界面

ok-gf2 的一个可选图形界面（不替换现有 Qt 界面，两者共用同一份配置），按 [MXU](https://github.com/MistEO/MXU)（MaaFramework 的通用 GUI 客户端）的交互和样式做：
顶栏一个流程一个页签（自带每日日常 / 周常 / 推图 / 工具，可以自己新建），流程由「块」组成（邮件一块、活动层一块……），底部「添加」面板里挑块加进当前流程，
每块的设置只属于它所在的流程；任务按游戏板块分组、卡片式勾选、一键预设、右侧运行状态 / 游戏画面 / 日志，深浅色和九种强调色。

## 怎么打开

| 方式 | 命令 | 说明 |
| --- | --- | --- |
| Windows 窗口 | `.venv\Scripts\python.exe tools\app_v2.py --port 8765` | 用 pywebview 开原生窗口；pywebview 是可选依赖，第一次用先 `.venv\Scripts\pip install pywebview` |
| 无边框窗口 | `tools\app_v2.py --frameless` | 和 MXU 一样由界面自绘标题栏（最小化 / 最大化 / 关闭），没在 Windows 上验证过，有问题去掉参数 |
| 浏览器 | `.venv\Scripts\python.exe tools\serve_web_v2.py --port 8765` | 浏览器打开 `http://127.0.0.1:8765/v2/`，不需要 pywebview |

新界面走 ok-script 的 Web 模式，需要额外装 `fastapi` 和 `uvicorn`（`.venv\Scripts\pip install fastapi uvicorn`），没装时启动会直接报缺模块。

ok 框架只允许一个实例：先关掉正在跑的 ok-gf2（桌面版、`serve_web.py`、另一个 app_v2），再开。

## 界面说明

- **顶栏**：一个流程一个页签 + 执行器状态；右边深浅色切换、设置。正在跑的那个流程的页签上有蓝色呼吸点，切到别的页签也能停。
  - 页签右边的「+」新建一个空流程（新建后直接改名，回车确认）；双击页签改名；右键页签有菜单：新建 / 复制这个流程 / 重命名 / 左移 / 右移 / 删除流程；悬停页签出现 × 删除（至少保留一个流程，删除要确认）。
  - 第一次打开按目录里的模板自动生成四个流程：**每日日常**（一键日常的 14 块）、**周常**（首领挑战 / 峰值推定 / 扩编实练）、**推图**（推图设置 + 阵容）、**工具**（启动游戏、性能诊断、调试工具、模板监控、测试任务）。它们和自建流程没有区别，都可以改名、增删块、删除。
- **块与流程**：一块 = 目录里的一个组件（如「领取邮件奖励」「喝水 / 吃饭 / 浇花 / 领逸趣奖励」「首领挑战」「推图设置」），对应某个任务类里的一个开关 + 几个选项键。
  底部工具栏「添加」打开 MXU 那种添加面板：搜索框 + 按游戏板块分组的块按钮，点一下加进当前流程，已加的变成 ✓，再点一下就移出（悬停变红色「移出」）；卡片右侧的垃圾桶也能移出。
  块加进流程（包括第一次生成的四个默认流程）时，会把后端当时的开关和选项值复制进来，之后这份值只属于这个流程，不用代码默认值（实录 2026-10-20：用默认值会把用户在后端关掉的「商店心愿单购买」悄悄打开）。
  **每块的选项、阵容都单独存在它所在的流程里**：在「速刷体力」里把活动层的「喝水」关掉，不会动「每日日常」里的活动层；改过的块标「已单独设置」，展开面板底部可「恢复默认值」或「从这个流程移出」。
  后端注册了但目录里没列的任务会出现在添加面板的「其它任务」组。
- **任务列表**：当前流程里的块按游戏板块分组，分组标题可折叠，右侧显示「已勾选/块数」。
  每张卡片：复选框 = 开始时这一块跑不跑；折叠时在名字后面预览选项值；点右侧箭头展开说明和选项；悬停出现垃圾桶 = 移出流程。
  整任务块（启动游戏、性能诊断这类）右侧有「运行」按钮单独跑；触发任务（模板监控）的复选框是后端启用/停用。
  左侧竖条：蓝色呼吸 = 正在执行；蓝 = 今日已完成；橙 = 今日待重试。
- **底部工具栏**：全选 / 折叠展开 / 预设（只有模板带预设的流程才显示）/ 添加；右边「开始」（运行中变红色「停止」，旁边出现暂停/继续）。
  「开始」时每个任务都先自动过一遍隐藏步骤「确保游戏已进入主页」（游戏没开就拉起并从标题页点进去，开着就直接开始，见 `docs/日常任务.md`），然后把流程里勾选的块所属的任务类按块的设置写进后端（这个任务的所有开关键：流程里勾了的开，其它一律关；选项键取块里记下的值；阵容写进「阵容与助战」），然后依次 start 这些任务（ok 框架会排队，一个跑完接着下一个）。
  所以同一时刻后端的配置总是「刚刚启动的那个流程」的，流程之间互不残留。
- **预设**：全套日常 / 快速收菜 / 只打体力，一键改勾选项（缺的块会补进来），定义在 `web_v2/public/catalog.json` 的 `presets`，模板用 `presets` 引用。
- **右侧面板**：运行状态（执行器、当前任务、今日已完成/待重试）、游戏画面（抓一帧 / 每 3 秒自动）、运行日志（级别 + 关键字过滤，默认滤掉 DEBUG 和识别噪音）。
  点日志标题可以把上面两个面板折起来放大日志；中间的分隔条可拖宽。
- **设置页**：外观（主题模式、强调色）；全局设置（从各板块抽出来、对整轮生效的日常项）；框架设置（ok-script 的设置组：阵容与助战、窗口等）；关于。

流程存在后端 `configs/workflows.json`（`GET/PUT /api/v2/workflows`，改动 0.5 秒后自动保存）；任务 / 全局设置的改动即时写回 `configs/`，没有保存按钮。

## 阵容：默认 → 全局 → 板块单独设置

编队和借助战按三层取值，越后越优先：内置默认（编队1、借助战开）→ 设置页「框架设置 · 阵容与助战」→ 流程里块卡片的「阵容」小卡（只属于那个流程，开始时写进全局组）。

- 场景登记在 `src/core/lineup_config.py` 的 `SCOPES`（推图、竞技场、体力本、班组、尘烟前哨战、活动、扩编实练），每个场景在全局组里有 `<场景>编队`（留空 = 沿用）和可借助战场景的 `<场景>助战`（沿用全局 / 开 / 关）。数据只存这一份。
- `catalog.json` 的组件用 `lineup_scopes` 声明用到哪些场景，展开卡片就显示对应的「阵容 · 场景」小卡：编队输入框的灰字是继承来的值，助战三段按钮标出全局当前值，单独设置过会标「已单独设置」，「恢复全局」一键清掉。这些值存在流程的块里，开始该流程时才写进全局组。
- 设置页「阵容与助战」卡片底部有各场景一览：全局值，以及哪些流程的哪些块单独覆盖了。
- 加新场景：`SCOPES` 里加一行，再在 catalog 对应条目的 `lineup_scopes` 里写上，界面不用改代码。

## 目录：组件库 + 模板

目录在 `web_v2/public/catalog.json`，是组件库，不再直接定义页签：

- `groups`：游戏板块（邮件、活动、限时开启、活动层……工具），每组若干 `components`（块）。块有 `id`、`label`、`task`（任务类名）、`enable_key`（在该任务里的开关键，纯选项块 / 整任务块为 null）、`keys`（块里显示的配置键，`"*"` 表示该任务全部键）、`lineup_scopes`、`doc`。
- `templates`：第一次打开（或 `workflows.json` 不存在）时生成的默认流程：`id`、`label`、`icon`、`desc`、`components`（块 id 列表）、`presets`（引用 `presets` 的 id）。
- `presets`：一键预设，`components` 是要勾上的块 id。
- `global_sections`：设置页「全局设置」的卡片。

加一块 = 在某个 group 的 `components` 里加一项；加一个默认流程 = `templates` 里加一项；都不用改代码。任务里没被任何块收编的键不会出现在流程里（去设置页的框架设置看）。
流程文件 `configs/workflows.json`：`{"version":1,"workflows":[{"id","label","icon","desc","presets","items":[{"uid","component","enabled","config":{键:值},"lineup":{"<场景>编队":...,"<场景>助战":...}}]}]}`。

## 实现

- `web_v2/`：Vite + React 19 + Tailwind 4 + lucide-react + zustand + sonner，`src/` 是源码，`static/` 是构建产物（随仓库提交，Windows 上不用装 node）。
- 样式、主题（`src/themes/presets`）、表单控件、卡片 / 面板 / 设置页布局来自 MXU（AGPL-3.0，许可证见 `web_v2/third_party/MXU-LICENSE`）。
- 数据走 ok-script Web 模式自带的 `/api`（tasks / status / settings / logs / tools/capture / events websocket），没有改框架；只加了 `tools/serve_web_v2.py` 里的 `/api/v2/workflows` 读写流程文件。
- 改界面：`cd web_v2 && npm install && npm run build`，提交 `static/`。本机联调：`npm run mock`（假后端，8765）+ `npm run dev`（5173，/api 代理到 8765）或 `npm run preview`（4173）。
- `tools/serve_web_v2.py` 把 `web_v2/static` 挂到 `/v2`；`tools/app_v2.py` 在其上套 pywebview 窗口。

## 已知限制

- 块的执行顺序固定按目录（ok 的一键日常本身顺序由代码决定），不支持拖动排序；同一块在一个流程里只能有一份。
- 「开始」把流程的设置写进后端后再启动，所以在任务运行中去改别的流程不会影响正在跑的这一轮，但下一轮以最后一次「开始」的流程为准。
- 没有多账户、定时执行页面；多账户相关开关在设置页「全局设置 · 日常通用」。
- 「教化」还没有实现，目录里也没列。
- 无边框模式（`--frameless`）未在 Windows 实机验证。
